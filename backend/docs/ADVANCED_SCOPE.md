# Advanced product scope

This implementation covers a defined host-and-vendor suite. It does not claim to include every feature offered by every wedding or event product worldwide. The scope uses representative planning and business workflows documented by [Aisle Planner](https://help.aisleplanner.com/en/articles/1899152-aisle-planner-subscription-plan-options), [HoneyBook smart files](https://help.honeybook.com/en/articles/5259399-smart-file-faqs), and [HoneyBook automations](https://help.honeybook.com/en/articles/6613606-start-automating-your-booking-process-in-honeybook) as research references. Those references are benchmarks, not integrations or endorsements.

## Host and planning operations

| Workspace                | Working behavior                                                                                                                                                      | Deliberate boundaries                                                                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Planning studio          | Twelve linked tools, planning progress, command search, account-specific event selection                                                                              | Progress derives from persisted checklist records; no fabricated AI or readiness score                                                                  |
| Seating studio           | Round/rectangular tables, pointer and keyboard arrangement, party assignment/unassignment, capacity enforcement, printable floor plan                                 | Grid is a planning layout, not a calibrated architectural drawing. Public party-size changes can produce a visible capacity warning requiring reseating |
| Celebration control room | Minute-level cues, day filters, responsible teams, notes, readiness/live/done transitions, owner-overlap warnings, print layout                                       | One live cue per event day is enforced transactionally; timings are operator-controlled                                                                 |
| Welcome desk             | QR invitation download, optional camera scan using ZXing, token/link lookup, per-day accepted RSVP verification, idempotent arrivals, party counts, undo, arrival log | Camera use needs browser permission on HTTPS/localhost. Hardware/camera availability is device-dependent; manual lookup remains available               |
| Multi-day RSVP           | Per-celebration responses, meal choices, allergies/dietary notes, companion allowance, public guest tokens, seating warnings                                          | RSVP deadline and invitation limits are enforced on the server                                                                                          |
| Planning circle          | Email-bound invitation tokens, editor/viewer access, time limits, owner-only invite/revoke, planner access expiry after event                                         | Invite links are copied/shared manually; external invitation email/SMS is not sent                                                                      |
| Celebration website      | Three themes, story, cover, dates/maps, FAQs, optional password, publish/private states, optimistic version checks, moderated guestbook, calendar file                | Website hosting uses the configured Next.js/API deployment; no custom-domain provisioning or external hosting automation                                |
| Inspiration atelier      | Image links, color swatches, notes, collections/tags, shared event access, deletion                                                                                   | Images use HTTPS URLs; binary upload and signed object storage are not implemented                                                                      |
| Shortlist and comparison | Persisted favorites, side-by-side prices/services/buffers/capacity, date holds, explained recommendations                                                             | Recommendations are deterministic planning matches, not an AI model or a guarantee of future availability                                               |

## Vendor, finance, and collaboration

| Workspace                  | Working behavior                                                                                                                                                                         | Deliberate boundaries                                                                                                                            |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Business suite             | New/qualified/proposal/won/lost pipeline, drag/drop or keyboard-accessible stage selection, inquiry values, notes, event dates, follow-up dates, pipeline totals                         | Leads are entered manually; no external email scraping or third-party lead sync                                                                  |
| Resource calendar          | Month view, separate resources/halls, reservation buffers, private client context, recurring date-pattern blackouts, conflict rollback, block removal                                    | Recurring rules materialize up to 90 days of same-day blocks; they do not silently extend forever                                                |
| Business team              | Owner-invited managers/viewers, separate permissions, expiry, revocation                                                                                                                 | Business invitees need vendor accounts. Invitation revocation disconnects live sockets; HTTP access is checked per request                       |
| Agreements                 | Vendor-issued fixed text, client review, exact account-name acknowledgement, timestamp/identity/hash record, withdrawal before signing, printable/exportable evidence                    | This is an application account acknowledgement, not a certificate-backed signature service. No legal enforceability claim is made                |
| Finance desk               | Booking-derived invoices, totals/capture history, CSV/PDF print, exact-balance installment creation, individual installment capture, idempotency, full balance settlement, refund status | All capture/refund operations are sandbox only. Invoice reference amounts do not add unconfigured taxes or gateway fees                          |
| Workflow automation        | Event-approaching, overdue-task, and exceeded-budget triggers; create-task/reminder actions; enable/disable; immediate check; persistent execution journal                               | Each rule executes once per event. Redis/BullMQ checks eligible rules every minute; there is no external SMS/email action                        |
| Insights                   | Host commitments/actuals, category breakdown, attendance/seating/checklist pulse; vendor pipeline/win rate/earnings/commissions/payout totals and six-month chart                        | Activity journal covers the instrumented advanced mutations, not every legacy request. No speculative financial forecasts are presented as facts |
| Marketplace administration | Category add/hide/restore, vendor activation/suspension, commission configuration, cancellation review, manual settlement ledger                                                         | Payout settlement is recorded after external settlement, not sent automatically                                                                  |

## Verification

The backend suite includes concurrency checks for booking holds, direct SQL exclusion, seating capacity, live run-sheet cues, check-in idempotency, automation retries, and installment capture. It also covers workspace isolation, invitation email/expiry/revocation, viewer privacy, website password/moderation/version checks, contract identity/fingerprint stability, recurring blackout rollback, CRM value preservation, and earnings reconciliation.

The browser suite verifies both the original workflows and advanced host/vendor operations, public website access, guestbook approval, account acknowledgement, milestone payment, live cue handling, QR token check-in, persistent seating changes, desktop/mobile overflow, and rendered minimum 14px text. Visual artifacts stay in `frontend/artifacts/` and are ignored by Git. Tests write development records; use disposable databases.

## External or future work

Live Bangladesh payment/refund gateways, external email/SMS delivery, bank payouts, signed object-storage uploads, certificate-backed signing, custom domains, hotel/travel inventory, gift-registry payment processing, AI-service integrations, offline check-in synchronization, and automated vendor-replacement orchestration are not implemented or falsely simulated. They require separate provider contracts, credentials, and implementation/testing. The original spec excludes full travel booking and live-streaming production tools.
