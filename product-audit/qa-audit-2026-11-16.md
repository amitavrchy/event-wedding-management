## Changes

- `e261a18`: make the Playwright base URL configurable and wait for checklist save completion before reload.
- `2cb31ff`, `430aa5b`: distinguish transient token refresh failures from session expiration, handle a rejected retry, and test those cases.
- `4a83396`: add Flutter CI and give the browser-only server a separate auth limit. Backend unit/integration tests still run with the normal default.
- `d19a7f8`, `e0cf654`: Android signing configuration, R8/resource shrinking, production endpoints, release script, generated icons, README and build-file ignore.
- `2dfcc94`: iOS metadata, Podfile, privacy manifest and project resource registration.

The first local Playwright run reproduced a 429 on the login step of the named test after repeated logins; two subsequent full runs passed with the browser server limit set to 200. The test also had an independent race when reloading after the checklist click. The original GitHub failure artifact was not inspected, so the 429 cannot be asserted as its proven cause.

## Remaining work and risks

- **P1:** Complete the quote-to-booking flow, including explicit service/date selection, transaction and exclusion-conflict handling, offline milestones, idempotence, both-party notifications, UI and tests. Existing accepted quotes have no booking; this is not release ready.
- **P1:** The complete Flutter-to-backend endpoint, response, auth and socket contract audit is unfinished. Sign-in/dashboard UI coverage and the requested full security review remain incomplete.
- **P2:** Bangla public pages, dynamic HTML language, locale switch and remaining destructive-action confirmations are unfinished.
- Release signing requires a real externally stored keystore and `android/key.properties`. The tested fallback is debug-signed and must not be published. Configure the deployed web server's `ANDROID_CERT_SHA256` to the actual Play signing certificate fingerprint; no credentials or fingerprints were supplied.
- iOS privacy manifest is a preliminary app-level declaration and requires verification against actual collected data, third-party SDK manifests and Apple required-reason API usage, plus legal/App Store privacy review before submission. Apple team and signing are intentionally untouched. Firebase remains unconfigured and optional. CocoaPods reported custom base configuration warnings; Flutter warns this project also uses Swift Package Manager. Verify integration during distribution preparation.
- Flutter 3.47.8 reports a future Kotlin Gradle plugin compatibility warning for `firebase_core`; track its plugin update. A deployment still requires operations to run the verified pipeline and update the server.
- The full phase 3 audit was not repeated after all changes; do not treat the partial checks below as a release gate.
